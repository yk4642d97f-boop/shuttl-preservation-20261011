# 双打：租卡前的数据与验收约定

当前可确认的是四人框接口和公开小样例，尚没有足够的四人击球归属/球种数据训练完整双打模型。
`data/drone_doubles/BD12_Rally1_1.csv` 是 130 帧、520 个框的样例；43 帧有球坐标，87 帧未标注。
原始 status 的语义未核实；绝不把 status=0 当非击球，也不把 (-1,-1) 当已确认不可见。

## 四人接口

沿用后端 `PlayerObservation`，每帧可有同侧两个不同 track_id；身份不能折叠成 near/far 两个槽位。
队伍侧（near/far）与球员身份分开：换边后队伍侧变化，球员/队伍身份不变。长遮挡后无法确认身份时记 unknown，
不自动把新出现的框当原球员。当前 HitNet/BST 两人模型遇到同帧同侧多人会拒绝，流水线记录 rules 回退。
2026-10-20 起可用 SHUTTL_HITNET_DOUBLES=1 打开实验性的 HitNet 配对模式（research/doubles/REPORT.md），BST 仍然跳过；默认行为不变。

准备正式标注时，每个源比赛登记 source_match_id、视频 SHA256、来源/许可、视角、场地、分辨率、实际逐帧 PTS。
片段记录原视频帧范围；训练/验证/测试按源比赛分组，来自同一比赛的剪辑和不同公开数据集副本不能跨组。

每帧分别标注：

- 四名球员的稳定 player_id、team_id、所在球场侧、框、遮挡状态；姿态点带可见性/未标注掩码。
- 球坐标及状态：visible / confirmed_invisible / unlabelled。只有人工确认不可见才是检测负样本。
- 接触事件：帧、击球 player_id（不确定可空）、球种（不确定可空）、人工置信度和复核状态。
- 回合起止、发球方、结束原因；无法从视频判断的落点/判罚保留 unknown。

未标注的击球帧/球种/身份均不进入对应监督损失。事件定位可评估而击球者未知时，只计定位指标。
训练数据导入前必须核对帧号与配对视频、FPS 和 PTS，现有 Drone CSV 缺这一步，不能直接转成击球训练集。

## 有数据后锁定的比较

1. 四人检测：按各球员/远近场报告召回，统计遮挡与相互重叠，不只报总框精度。
2. 跟踪：IDF1/HOTA、身份交换次数、持续遮挡后重关联；按源比赛汇总。
3. 击球：一对一匹配 ±2 帧，同时报 FP/FN、发球召回和每分钟连续录像误报。
4. 归属：匹配击球中的四选一身份正确率，以及漏检也计失败的联合指标；只预测近远侧不能代替。
5. 球种：定位+归属+球种联合 F1、逐类别召回，未知标签掩码公开。
6. 体验：整段上传成功率、耗时、GPU 峰值显存、重启恢复、报告时间戳同步。

首轮先建立来源隔离的小规模标注基线，再按失败类型扩充。没有独立场地、视角、球员与连续录像评测，
不能使用“顶尖双打模型”作为验收结论。现有单打测试不可用来替代。
